## Task 1 — Desktop row fit (BLOCKING)

**Fails at 1024px.** The `dense = navItems.length > 6` heuristic in `Navbar.tsx` counts
top-level entries only; football now has exactly 6 (Home, Matches, Picks, Record, Play,
News), so `dense` stays `false` and the nav uses the `lg` (1024px) breakpoint instead of
`xl`. At 1024px the content genuinely does not fit.

Measured (`document.documentElement.scrollWidth` vs `clientWidth`, viewport height 900,
Champions League active — same widths regardless of competition since group labels, not
item counts, drive nav width):

| Viewport | Row content width needed | Available | Overflow / free space | Result |
|---|---|---|---|---|
| **1024px** | **1048px** | 1024px | **−24px (overflows)** | **FAIL** |
| 1152px | 1128px | 1152px | +24px | PASS |
| 1280px | 1256px | 1280px | +24px | PASS |
| 1440px | 1336px | 1440px | +104px | PASS |
| 1920px | 1576px | 1920px | +344px | PASS |

At 1024px: `scrollWidth: 1048, clientWidth: 1024` — a real 24px horizontal overflow on the
page, not just a visual clip. Screenshot (`header_1024.png`) shows the ticker row cut off
("CALIBRATED CONFIDENCE · WHAT WE SHOW IS…") and the **Sign In / Sign Up button visibly
truncated** at the right edge ("SIGN U" instead of "SIGN IN / SIGN UP"). At 1152px (next
tested size up) everything fits cleanly with 24px to spare — confirmed visually.

This is not a redesign call for me to make (per instructions), so I'm flagging it rather
than picking a fix. Two directions Kazim could choose from, for reference only:
- bump the `dense` threshold check to `>= 6` (or compare against `xl` unconditionally once
  count is 6), or
- the real fix is a measured breakpoint, not a count heuristic, since a 6th short label
  could fit at 1024 while a 6th long one might not at 1152 either.

## Motion / `prefers-reduced-motion` — observation only, pre-existing

`NavLinks.tsx` (untouched by this diff) animates the hover pill and active-state dot via
`motion/react`'s `layoutId`. `globals.css` has a reduced-motion block targeting `.nav-pill`
/`.nav-link` classes, but the live component doesn't use those class names (it builds
classes inline via `linkClass`/`cx`), so that CSS rule doesn't actually reach these
animations — `prefers-reduced-motion: reduce` would not stop them. This predates today's
change (file not in the diff) and isn't something I fixed, flagging for the record since
the QA checklist calls it out explicitly.
